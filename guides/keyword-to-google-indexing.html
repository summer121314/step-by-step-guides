第三篇 · 2026年10月实操记录

从零找关键词、做工具网站，再提交 Google 收录：完整实战教程

一次真实的出海工具网站实验：从不确定做什么网站，到研究英文搜索词、建立 GitHub 仓库、上线 Vercel，再配置 Analytics 与 Google Search Console。这是操作记录，不是流量或收益保证；各平台界面可能变化。

这篇教程你会完成什么？

发现候选关键词 → 识别搜索需求和竞争 → 选择 MVP → 使用 ChatGPT 开发与测试 → GitHub 托管代码 → Vercel 上线 → Google Search Console 验证、提交 Sitemap 和申请收录。

实际案例：LedgerBridge Lab，目前定位是 QuickBooks CSV 导入前的数据检查与格式整理工具。它的 QBO 真实兼容性尚未通过验收。

01. 从问题出发，而不是先写代码

选择适合新站的工具关键词，最好同时考虑：用户是否有清晰任务、有没有现成竞品、开发与测试是否可控、搜索需求是否足以支撑长期维护。工具名字听起来好听，不代表真的有人会搜索。

这次先试了 csv import validator、csv validator、csv converter，再追踪到 csv to qbo converter 等更具体的长尾词。

02. 用 Semrush 寻找长尾关键词

  1. 进入 Semrush，打开 Keyword Magic Tool。
  2. 目标如果是英文、美国用户，把数据库设为 United States。
  3. 分别搜索主词和变体，查看 Volume（估计月搜索量）、KD（关键词难度）、CPC（广告主估计点击价）。
  4. 单独记录真正对应产品功能的词，不要把全部相关词的流量相加，当成自己一定能获得的访问量。
  5. 手动搜索 Google，观察结果是工具、教程、论坛还是商业产品，并点击竞品实际试用。
当时看到的参考数据（Semrush 估计值，可能随时间变化）

csv to qbo converter：Volume 约 1,300 / 月，KD 约 5，CPC 约 US$10.23；csv to qbo converter free：Volume 约 590 / 月，KD 约 2，CPC 约 US$9.80；csv to qbo converter free online：Volume 约 390 / 月，KD 约 5。

这些数字说明值得进一步调查，不表示你能获得对应流量，也不表示广告发布者能拿到这个 CPC 收入。KD 低同样不等于竞争一定容易。

03. 判断关键词是不是“能做的产品”

关键词筛选不能只看数字。我们搜索发现，QuickBooks Online 自身就支持部分 CSV 直接导入；真正的 .qbo Web Connect 文件涉及金融机构标识、交易唯一性、账户余额等要求。简单改文件扩展名不能解决问题。

因此 MVP 选择了更稳妥的路线：先做银行 CSV 日期、金额和字段检查，支持导出适合 QuickBooks Online 手工导入的三列和四列 CSV；QBO 导出仅用合成测试数据演示，不对真实账务宣称兼容。选题分析后可以调整定位，不必被原始关键词绑住。

04. 请 ChatGPT 给出产品计划和网站代码

把需求说清楚：目标用户是谁、输入什么、输出什么、错误如何显示、哪些数据不能上传、哪些功能尚未验证。可以复制修改这个提示词：

请为美国 QuickBooks 用户设计一个英文 CSV 导入检查工具。
要求：在浏览器本地解析 CSV；支持日期、描述、正负金额，以及 Debit/Credit 分列；
显示无效日期、零金额、重复交易警告；输出三列或四列 CSV；
手机也能使用；包含 FAQ、隐私与风险说明；
不要声称未经实际测试的 QBO 文件可以正常导入。
请给出可测试代码和边界条件测试计划。

要特别要求测试：引号、逗号、跨行描述、日期歧义、收入支出方向、空字段、重复记录、超过文件大小限制的情况。下载成功不代表导入兼容，涉及财务数据必须再做人工核对与真实软件验收。

05. 在 GitHub 建立代码仓库

  1. 登录 GitHub New repository。
  2. 输入新仓库名称（本案例：ledgerbridge-qbo），选择 Public（公开代码会被所有人看到）。
  3. 创建空仓库后，让已获得授权的 ChatGPT GitHub 连接上传网页和 JavaScript 文件；若没有连接则手动上传。
  4. 回仓库检查文件和提交记录，不得上传密码、API Key、真实银行流水或个人身份资料。

这个项目采用静态 HTML、CSS、JavaScript，首页 index.html、样式 style.css、功能代码 app.js 分开，方便继续维护。

06. Vercel 上线：遇到权限问题怎么办

  1. 打开 Vercel New Project，选择 GitHub 仓库并导入。
  2. 如果列表里找不到新仓库，选择 Adjust GitHub App Permissions，在 GitHub 给 Vercel 新仓库访问权限，再回 Vercel 刷新。
  3. 静态网站可选择 Framework Preset: Other、Root Directory: ./，然后点击 Deploy。
  4. 出现 Congratulations! 后进入项目，在 Domains 找到正式站点网址。
  5. 网站后续有代码提交时，Vercel 通常会自动重新部署；确认 Production Deployment 状态为 READY，而非只看 ChatGPT 说“已完成”。
注意托管的商业用途

Vercel Hobby 免费方案仅限非商业用途。若今后放 Google AdSense 广告或收取工具使用费，请先选择允许商业使用的托管方案；不要默认“免费部署”就允许商业化。

07. 免费统计：Vercel Analytics

在项目中启用 Web Analytics。使用普通静态 HTML 时，通常还要在页面的 <head> 添加：

<script defer src="/_vercel/insights/script.js"></script>

等待新部署 READY 后自己访问几次，再到 Vercel Analytics 检查。统计启用前的访客不会自动补录。

08. 配置 Google Search Console

  1. 打开 Google Search Console，选择 URL プレフィックス（URL 前缀）。
  2. 输入完整网址，例如 https://ledgerbridge-qbo.vercel.app/，协议、域名、结尾斜杠要一致。
  3. 选择 HTML タグ，复制 Google 给你的 google-site-verification Meta 标签。
  4. 把标签放进网站首页 <head> 并部署，确认新版本 READY，再回 Google 点击 確認。
  5. 出现 所有権を確認しました 说明所有权验证通过；但并不等于页面已经被 Google 收录。

网站的 sitemap.xml 要写真实网址并放在网站根目录；robots.txt 可以指向它。提交前检查网站地图能通过公开网址访问，不要保留示例占位域名。

09. 提交 Sitemap、申请 Google 收录

  1. 在 Search Console 选择对应网站，点击左侧 サイトマップ。
  2. 输入 sitemap.xml，点击 送信；出现 成功しました 表示提交成功。
  3. 在 URL 検査 中输入首页地址，按提示点击 インデックス登録をリクエスト。
  4. 若出现 インデックス登録をリクエスト済み，说明申请已发送，不等于已收录。
  5. 若弹出 割り当て量を超えています，表示达到了当天请求配额。不要一直重试，隔天再试；正常的 Sitemap 发现机制仍可能让 Google 自动抓取。

重要：Search Console 验证成功、Sitemap 成功、手动请求已提交，这三件事与“正式收录、获得排名、产生点击”不是一回事。搜索结果出现可能需要等待，且没有保证。

10. 上线后的检查清单

  • 网页可通过公开网址打开，手机操作正常。
  • 示例文件、错误提示、CSV 下载均经过测试。
  • GitHub 文件与 Vercel 最新部署对应。
  • 标题、Meta 描述、Canonical、Sitemap、robots.txt 配置一致。
  • Analytics 有新的页面浏览数据；Search Console 已验证并提交 Sitemap。
  • 未来有商业化计划时，另行处理托管条款、隐私声明、广告审核与税务事宜。

11. 下一步：观察数据，而不是每天重复申请

观察 Search Console 的曝光、点击和搜索词，以及 Analytics 的访问趋势。如果几周后长期没有曝光，优先检查页面是否解决真实问题、竞品质量、关键词意图和工具是否真正可用。不要把第三方估计搜索量当成收入预测。
